Binary Search（二分探索）

ソート済みの配列から値や境界を高速に探す二分探索について解説します.

参考：アルゴ式

二分探索について

二分探索は,あらかじめソートされたデータの中から目的の値を高速に見つけるアルゴリズムです.
真ん中の値と比べて「答えは左半分か右半分か」を決め,探す範囲を毎回半分にしていきます.

代表的な使い道は次のとおりです.

  • ソート済みの配列に値 x があるか,どこにあるかを調べる
  • 「x 以上の要素の個数」「x 以上で最小の値」などを求める
  • 「条件を満たす最小の値」を求める(答えで二分探索)

Python では標準ライブラリの bisect で書けます.

from bisect import bisect_left, bisect_right

A = [10, 20, 30, 30, 30, 40]  # ソート済み
print(bisect_left(A, 30))     # 30 以上が始まる位置
print(bisect_right(A, 30))    # 30 より大きいが始まる位置
print(bisect_right(A, 30) - bisect_left(A, 30))  # 30 の個数

操作計算量
先頭から順に探す(線形探索)$O(N)$
二分探索(bisect_left / bisect_right)$O(\log N)$
二分探索の前のソート(sort / sorted)$O(N \log N)$
ソートを保ったまま挿入(insort)$O(N)$

二分探索のしくみ

ソート済みの配列 A から 72 を探す例で見ていきます.
探す範囲を [left, right] とし,その真ん中 mid = (left + right) // 2 の値と 72 を比べます.

  • A[mid] < 72 なら,72 は mid より右にあるので left = mid + 1
  • A[mid] > 72 なら,72 は mid より左にあるので right = mid - 1
  • A[mid] == 72 なら見つかったので終了

クリックで1段階ずつ確認できます.

なぜ $O(\log N)$ なのか

1回比べるごとに探す範囲が半分になるので,$N$ 個の範囲は $k$ 回で $N / 2^k$ 個になります.
範囲が1個になるまでの回数は $\log_2 N$ 回程度なので,計算量は $O(\log N)$ です.
比較の回数は最大でも次の程度で,$N$ が大きいほど線形探索($O(N)$)との差が大きくなります.

境界を探す二分探索

実際の問題では「ちょうど x の位置」よりも,「x 以上の値が始まる位置」のような条件を満たす最小の位置(境界)を探すことが多いです.
条件がある位置を境に「満たさない → 満たす」と切り替わるとき,次の手順で境界を求められます.

  • ng は常に条件を満たさない側,ok は常に条件を満たす側に置く(最初は ng = -1, ok = N)
  • 真ん中 mid が条件を満たせば ok = mid,満たさなければ ng = mid にする
  • ok と ng が隣り合ったら終了.ok が答え

この形なら値が見つからない場合や重複がある場合も同じように扱えるので,下の実装ではこちらを使います.
また,条件は配列の値でなくてもよく,「$x^2 \ge 1000$ を満たす最小の整数 $x$」のように答えの値そのものを二分探索することもできます.

クラスでの実装

クラスを用いると以下のように実装することができます.
競技プログラミングでよく使う,単調増加する関数 $f(x)$ の値で二分探索する形です.
$f$ を渡しておくと,「$f(x) \ge$ target となる最小の $x$」「$f(x) \le$ target となる最大の $x$」を整数・実数の範囲で求められます.
中身は上の ok / ng の二分探索です.

class BinarySearch:
    # f は単調増加(x が大きいほど f(x) も大きいか等しい)な関数
    def __init__(self, f):
        self.f = f

    # f(x) >= target となる最小の整数 x を [lo, hi] から探す (なければ hi + 1)
    def min_x(self, target, lo, hi):
        ng, ok = lo - 1, hi + 1 # ng 側は常に条件を満たさない,ok 側は常に満たすとみなす
        while ok - ng > 1:
            mid = (ok + ng) // 2
            if self.f(mid) >= target:
                ok = mid # 答えは mid 以下
            else:
                ng = mid # 答えは mid より大きい
        return ok

    # f(x) <= target となる最大の整数 x を [lo, hi] から探す (なければ lo - 1)
    def max_x(self, target, lo, hi):
        ok, ng = lo - 1, hi + 1
        while ng - ok > 1:
            mid = (ok + ng) // 2
            if self.f(mid) <= target:
                ok = mid # 答えは mid 以上
            else:
                ng = mid # 答えは mid より小さい
        return ok

    # f(x) >= target となる最小の実数 x を [lo, hi] から探す (回数を決めて範囲を半分にし続ける)
    def min_x_real(self, target, lo, hi, n_iter=100):
        for _ in range(n_iter):
            mid = (lo + hi) / 2
            if self.f(mid) >= target:
                hi = mid
            else:
                lo = mid
        return hi

# 例1: f(x) = x^2
bs = BinarySearch(lambda x: x * x)
print(bs.min_x(1000, 0, 1000)) # x^2 >= 1000 となる最小の整数
print(bs.max_x(1000, 0, 1000)) # x^2 <= 1000 となる最大の整数
print(bs.min_x_real(2, 0, 2)) # x^2 >= 2 となる最小の実数 (√2)

# 例2: f(i) = A[i] (ソート済みなので単調増加)
A = [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91, 99]
bs = BinarySearch(lambda i: A[i])
print(bs.min_x(72, 0, len(A) - 1)) # A[i] >= 72 となる最小の i (bisect_left(A, 72) と同じ)
print(bs.max_x(38, 0, len(A) - 1) + 1) # 38 以下の要素の個数 (bisect_right(A, 38) と同じ)

# 例3: 答えで二分探索.作るのに T[i] 分かかる機械で,10 個作るのにかかる最短の時間
T = [2, 3, 7]
bs = BinarySearch(lambda t: sum(t // ti for ti in T)) # t 分で作れる個数
print(bs.min_x(10, 0, 10**18))

例3のように,「答えを $t$ と決めたら条件を満たすか判定できる」「$t$ が大きいほど条件を満たしやすい」問題は,答えの値で二分探索できます.
探す範囲の幅を $W$ とすると,$f$ を呼ぶ回数は $O(\log W)$ 回です.例3では $W = 10^{18}$ でも 60 回程度で済みます.
実数版はループを抜ける条件を誤差で決めると無限ループになることがあるので,回数(100回なら幅は $2^{-100}$ 倍)で決めるのが安全です.

ライブラリでの実装

Python の標準ライブラリには bisect モジュールが存在します.
ソート済みのリストに対して,ソート順を崩さずに値を挿入できる位置を二分探索で求めます.
配列の中を探すだけなら,クラスよりもこちらの方が短く書けます.

from bisect import bisect_left, bisect_right

A = [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91, 99]

i = bisect_left(A, 72)
print(i, A[i] == 72) # 72 は 9 番目にある
print(bisect_left(A, 50)) # 50 以上で最小の値 (56) の位置
print(bisect_right(A, 38)) # 38 以下の要素の個数

操作操作内容計算量
bisect_left(A, x)x を挿入できる最も左の位置を返す(x 以上の要素が始まる位置)$O(\log N)$
bisect_right(A, x)

insort は位置を探すのは $O(\log N)$ ですが,リストの要素をずらして挿入するので全体で $O(N)$ かかります.
挿入や削除をくり返しながら二分探索したいときは SortedContainers の SortedList を使います.

bisect_left と bisect_right の違い

探す値がリストにあるとき,bisect_left はその値の左端,bisect_right は右端の次の位置を返します.
値がリストにないときは,どちらも同じ位置を返します.

個数の数え方

どちらも「返り値 = それより左にある要素の個数」になっているので,個数を数えるのにそのまま使えます.

求めたいもの書き方
x 未満の要素の個数bisect_left(A, x)
x 以下の要素の個数bisect_right(A, x)
x 以上の要素の個数len(A) - bisect_left(A, x)
x より大きい要素の個数len(A) - bisect_right(A, x)
l 以上 r 未満の要素の個数bisect_left(A, r) - bisect_left(A, l)
x 以上で最小の値A[bisect_left(A, x)](位置が len(A) なら存在しない)
x 以下で最大の値A[bisect_right(A, x) - 1](位置が -1 なら存在しない)

ソートの計算量に注意

二分探索はソート済みのデータにしか使えません.
Python の sort() や sorted() は Timsort というアルゴリズムで,$O(N \log N)$ でソートできます.
ソートは最初に1回だけ行い,その後に二分探索を何回もするのが基本の形です.
二分探索のたびにソートし直すと,1回あたり $O(N \log N)$ かかってしまい,二分探索を使う意味がなくなります.
