Binary Search（二分探索）

ソート済みの配列から値や境界を高速に探す二分探索について解説します.

参考：アルゴ式

二分探索について

二分探索は,あらかじめソートされたデータの中から目的の値を高速に見つけるアルゴリズムです.
真ん中の値と比べて「答えは左半分か右半分か」を決め,探す範囲を毎回半分にしていきます.

代表的な使い道は次のとおりです.

  • ソート済みの配列に値 x があるか,どこにあるかを調べる
  • 「x 以上の要素の個数」「x 以上で最小の値」などを求める
  • 「条件を満たす最小の値」を求める(答えで二分探索)

Python では標準ライブラリの bisect で書けます.

from bisect import bisect_left, bisect_right

A = [10, 20, 30, 30, 30, 40]  # ソート済み
print(bisect_left(A, 30))     # 30 以上が始まる位置
print(bisect_right(A, 30))    # 30 より大きいが始まる位置
print(bisect_right(A, 30) - bisect_left(A, 30))  # 30 の個数
2
5
3
操作計算量
先頭から順に探す(線形探索)$O(N)$
二分探索(bisect_left / bisect_right)$O(\log N)$
二分探索の前のソート(sort / sorted)$O(N \log N)$
ソートを保ったまま挿入(insort)$O(N)$

二分探索のしくみ

ソート済みの配列 A から 72 を探す例で見ていきます.
探す範囲を [left, right] とし,その真ん中 mid = (left + right) // 2 の値と 72 を比べます.

  • A[mid] < 72 なら,72 は mid より右にあるので left = mid + 1
  • A[mid] > 72 なら,72 は mid より左にあるので right = mid - 1
  • A[mid] == 72 なら見つかったので終了

クリックで1段階ずつ確認できます.

なぜ $O(\log N)$ なのか

1回比べるごとに探す範囲が半分になるので,$N$ 個の範囲は $k$ 回で $N / 2^k$ 個になります.
範囲が1個になるまでの回数は $\log_2 N$ 回程度なので,計算量は $O(\log N)$ です.
比較の回数は最大でも次の程度で,$N$ が大きいほど線形探索($O(N)$)との差が大きくなります.

二分探索の実装

上の図の手順をそのままコードにすると,次のようになります.

A = [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91, 99]
target = 72
left, right = 0, len(A) - 1   # 探す範囲 [left, right]
while left <= right:
    mid = (left + right) // 2
    print(f"A[{mid}] = {A[mid]} と比較")
    if A[mid] == target: break
    elif A[mid] < target: left = mid + 1   # 右半分に絞る
    else: right = mid - 1                  # 左半分に絞る
print(f"{target} は {mid} 番目")
A[5] = 23 と比較
A[8] = 56 と比較
A[10] = 91 と比較
A[9] = 72 と比較
72 は 9 番目

値が見つからないときは left > right になってループを抜けます.

境界を探す二分探索

実際の問題では「ちょうど x の位置」よりも,条件を満たす最小の位置(境界)を探すことが多いです.
条件 is_ok(x) が,ある位置を境に False から True に切り替わるとき,次の形で境界を求められます.

  • ng は常に条件を満たさない側,ok は常に条件を満たす側に置く
  • 真ん中が条件を満たせば ok を,満たさなければ ng を動かす
  • ok と ng が隣り合ったら終了.ok が答え
A = [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91, 99]
def is_ok(i):
    return A[i] >= 50  # 50 以上か

ng, ok = -1, len(A)  # A[-1] は条件を満たさない,A[len(A)] は満たすとみなす
while ok - ng > 1:
    mid = (ok + ng) // 2
    if is_ok(mid): ok = mid
    else: ng = mid
print(ok)
8

これは bisect_left(A, 50) と同じ値です.
is_ok は配列の値でなくてもよく,「$x^2 \ge 1000$ を満たす最小の整数 $x$」のように答えの値そのものを二分探索することもできます(ng, ok = 0, 1000 として is_ok = lambda x: x * x >= 1000 にすると 32 が求まります).

bisect を用いた二分探索

Python の bisect モジュールは,ソート済みのリストに対して,ソート順を崩さずに値を挿入できる位置を二分探索で求めます.
自分で二分探索を書くよりも短く,間違いも起きにくいので,配列の二分探索はこれを使うのがおすすめです.

bisect_left と bisect_right の違い

探す値がリストにあるとき,bisect_left はその値の左端,bisect_right は右端の次の位置を返します.
値がリストにないときは,どちらも同じ位置を返します.

どちらも「返り値 = それより左にある要素の個数」になっているので,個数を数えるのにそのまま使えます.

求めたいもの書き方
x 未満の要素の個数bisect_left(A, x)
x 以下の要素の個数bisect_right(A, x)
x 以上の要素の個数len(A) - bisect_left(A, x)
x より大きい要素の個数len(A) - bisect_right(A, x)
l 以上 r 未満の要素の個数bisect_left(A, r) - bisect_left(A, l)
x 以上で最小の値A[bisect_left(A, x)](位置が len(A) なら存在しない)
x 以下で最大の値A[bisect_right(A, x) - 1](位置が -1 なら存在しない)

操作一覧

操作操作内容計算量
bisect_left(A, x)x を挿入できる最も左の位置を返す(x 以上の要素が始まる位置)$O(\log N)$
bisect_right(A, x)
bisect(A, x)		x を挿入できる最も右の位置を返す(x より大きい要素が始まる位置)$O(\log N)$
insort_left(A, x)bisect_left の位置に x を挿入する$O(N)$
insort_right(A, x)
insort(A, x)		bisect_right の位置に x を挿入する$O(N)$

insort は位置を探すのは $O(\log N)$ ですが,リストの要素をずらして挿入するので全体で $O(N)$ かかります.
挿入や削除をくり返しながら二分探索したいときは SortedContainers の SortedList を使います.

ソートの計算量に注意

二分探索はソート済みのデータにしか使えません.
Python の sort() や sorted() は Timsort というアルゴリズムで,$O(N \log N)$ でソートできます.
ソートは最初に1回だけ行い,その後に二分探索を何回もするのが基本の形です.
二分探索のたびにソートし直すと,1回あたり $O(N \log N)$ かかってしまい,二分探索を使う意味がなくなります.

練習問題

解答例はクリックで開きます.

最小の添字(アルゴ式)

小さい順に並んだ A と,B の各値 b について,$A_x \ge b$ となる最小の $x$ を求める問題です.
「b 以上が始まる位置」なので bisect_left そのものです.全体で $O(M \log N)$ です.

解答例 
from bisect import bisect_left

N, M = map(int, input().split())
A = list(map(int, input().split()))  # すでにソート済み
B = list(map(int, input().split()))
for b in B:
    print(bisect_left(A, b))

小さい数の個数(アルゴ式)

B の各値 b について,$A_x \le b$ となる $x$ の個数を求める問題です.
A はソートされていないので,最初に1回ソートします.b 以下の個数は bisect_right で求まります.全体で $O((N + M) \log N)$ です.

解答例 
from bisect import bisect_right

N, M = map(int, input().split())
A = sorted(map(int, input().split()))
B = list(map(int, input().split()))
for b in B:
    print(bisect_right(A, b))  # b 以下の個数

整数なら bisect_left(A, b + 1)(b + 1 未満の個数)でも同じ値になります.

和が K 以上のペア(アルゴ式)

$A_i + A_j \ge K$ となる組 $(i, j)$ の個数を求める問題です($i = j$ も含みます).
$i$ を固定すると,条件は $A_j \ge K - A_i$ になるので,「$K - A_i$ 以上の個数」を二分探索で数えます.全体で $O(N \log N)$ です.

解答例 
from bisect import bisect_left

N, K = map(int, input().split())
A = sorted(map(int, input().split()))
ans = 0
for a in A:
    ans += N - bisect_left(A, K - a)  # K - a 以上の個数
print(ans)

何番目の重さ？(アルゴ式)

重さがすべて異なる $N$ 個のボールについて,それぞれ何番目に軽いか(0番目から数える)を求める問題です.
「何番目に軽いか」は「自分より軽いボールの個数」なので,ソートしたリストで bisect_left を使います.全体で $O(N \log N)$ です.

解答例 
from bisect import bisect_left

N = int(input())
W = list(map(int, input().split()))
S = sorted(W)
for w in W:
    print(bisect_left(S, w))  # w より軽いボールの個数

Min Difference(AtCoder ABC212 C)

$|A_i - B_j|$ の最小値を求める問題です.
各 a について,B の中で a に一番近いのは「a 以上で最小の値」か「a 未満で最大の値」のどちらかです.
B をソートしておき,bisect_left で求めた位置とその1つ左を調べます.全体で $O((N + M) \log M)$ です.

解答例 
from bisect import bisect_left

N, M = map(int, input().split())
A = list(map(int, input().split()))
B = sorted(map(int, input().split())) + [float("inf")]  # 番兵
ans = float("inf")
for a in A:
    i = bisect_left(B, a)  # B[i] が a 以上で最小,B[i - 1] が a 未満で最大
    ans = min(ans, B[i] - a, abs(a - B[i - 1]))
print(ans)

末尾に無限大(番兵)を足しておくと,i が範囲外になる場合の場合分けが不要になります.
i = 0 のときの B[i - 1] も番兵(B[-1])になり,差が無限大になるので答えに影響しません.

Reindeer and Sleigh(AtCoder ABC334 D)

ソリ $i$ を引くにはトナカイが $R_i$ 頭必要で,トナカイ $X$ 頭で最大何台のソリを引けるかを答える問題です.
台数を多くするには,必要な頭数が少ないソリから選ぶのが最適です.
R をソートして累積和 S を作ると,S[k - 1] が「$k$ 台引くのに必要な頭数」になるので,X 以下の個数を bisect_right で数えます.
全体で $O(N \log N + Q \log N)$ です.

解答例 
from bisect import bisect_right
from itertools import accumulate

N, Q = map(int, input().split())
R = sorted(map(int, input().split()))
S = list(accumulate(R))  # S[k - 1] = k 台引くのに必要な頭数
for _ in range(Q):
    X = int(input())
    print(bisect_right(S, X))  # X 頭以下で引ける台数
