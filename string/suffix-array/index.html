Suffix Array（接尾辞配列）

部分文字列を便利に扱えるデータ構造について解説します.

Suffix Arrayについて

Suffix Arrayは,文字列のすべての接尾辞を辞書順に並べたときの開始位置の配列です.
接尾辞がソートされているので,ある文字列 T が部分文字列として含まれるかを二分探索で調べたり,LCP配列と組み合わせて異なる部分文字列の個数を数えたりできます.

操作計算量
Suffix Arrayの構築(SA-IS法)$O(N)$
文字列 T の検索(二分探索)$O(|T|\log N)$
LCP配列の構築(ACLの lcp_array)$O(N)$

Suffix Arrayとはなにか

まずは次のような配列を考えます.
要素 i に,文字列 S の i 番目から末尾までの部分文字列をもつ配列.
具体的には下記のようになります.

文字列 S = "SuffixArray" のとき

suffix[0]  = "SuffixArray"
suffix[1]  = "uffixArray"
suffix[2]  = "ffixArray"
suffix[3]  = "fixArray"
suffix[4]  = "ixArray"
suffix[5]  = "xArray"
suffix[6]  = "Array"
suffix[7]  = "rray"
suffix[8]  = "ray"
suffix[9]  = "ay"
suffix[10] = "y"

次にこれを辞書順でソートしたときの開始位置を要素に持つ配列を SuffixArray といいます.
具体的には下記のようになります（小文字は大文字よりも後ろに来る）.

sa[0]  = 6   # "Array"
sa[1]  = 0   # "SuffixArray"
sa[2]  = 9   # "ay"
sa[3]  = 2   # "ffixArray"
sa[4]  = 3   # "fixArray"
sa[5]  = 4   # "ixArray"
sa[6]  = 8   # "ray"
sa[7]  = 7   # "rray"
sa[8]  = 1   # "uffixArray"
sa[9]  = 5   # "xArray"
sa[10] = 10  # "y"

SA-IS法というアルゴリズムを用いることで,文字列長を N としたときにこの配列を $O(N)$ で取得することができます.

操作一覧

操作操作内容計算量
suffix_array(s)文字列 s のSuffix Arrayを返す$O(N)$
lcp_array(s, sa)辞書順で隣り合う接尾辞どうしの最長共通接頭辞の長さ(長さ N-1)を返す$O(N)$

使い方

SuffixArrayからソートされた任意の長さの部分文字列を復元し,二分探索などに利用できます.$O(|S|N)$

from atcoder.string import suffix_array
S = "SuffixArray"
sa = suffix_array(S)

S_sorted = []
N = 2
for i in sa:
    S_sorted.append(S[i:i+N])
print(S_sorted)
['Ar', 'Su', 'ay', 'ff', 'fi', 'ix', 'ra', 'rr', 'uf', 'xA', 'y']

SA-IS法のしくみ

接尾辞をそのままソートすると,文字列どうしの比較1回に最大 $O(N)$ かかるので全体で $O(N^2 \log N)$ になってしまいます.
SA-IS法は,「一部の接尾辞(LMS)の順番さえ分かれば,残りは決まった順に流し込むだけで全体の順番が決まる」という性質(誘導ソート)を使って,$O(N)$ でSuffix Arrayを作ります.
ACLの suffix_array も,ある程度長い文字列では内部でSA-IS法を使っています.

ここでは S = banana を例にします.末尾に,どの文字よりも小さい特別な文字(番兵) $ を付けて banana$ として考えます.

手順1:接尾辞を S型 と L型 に分ける

接尾辞 i が,1つ右の接尾辞 i+1 より

  • 小さいとき S型(Smaller)
  • 大きいとき L型(Larger)

とします.これは文字列を比較しなくても,右から1文字ずつ見るだけで決められます.

  • 番兵 $ は S型
  • S[i] < S[i+1] なら S型,S[i] > S[i+1] なら L型
  • S[i] = S[i+1] なら,i+1 と同じ型

例えば i = 4 は n > a なので L型,i = 3 は a < n なので S型です.

i文字接尾辞型LMS
0bbanana$L
1aanana$S○
2nnana$L
3aana$S○
4nna$L

手順2:LMS を見つける

S型のうち,左隣が L型のものを LMS(Left-Most S)と呼びます.
文字の大小を山と谷に見立てると,LMS は「下り坂のあとの谷の底」にあたる位置です.
banana$ では 1,3,6 が LMS です(上の表の ○).LMS は隣り合わないので,多くても N/2 個しかありません.

手順3:バケツに分ける

Suffix Arrayでは,同じ文字で始まる接尾辞は必ずひとかたまりに並びます.
そこで SA を先頭の文字ごとの区画(バケツ)に分けておきます.banana$ なら $ が1個,a が3個,b が1個,n が2個です.

さらに,同じバケツの中では L型が前,S型が後ろに並びます.
例えば a のバケツでは,L型の a$ は a のあとに a より小さい文字が来て,S型の ana$ は a より大きい文字が来るので,L型の方が必ず小さくなります.

手順4:誘導ソート

LMS の正しい順番が分かっているとすると,次の2回の走査だけで全体の順番が決まります.

  1. LMS を正しい順番で,それぞれのバケツの末尾に置く
  2. SA を左から見て,入っている値 i の1つ前 i−1 が L型なら,i−1 をそのバケツの先頭から詰めて入れる
  3. SA を右から見て,入っている値 i の1つ前 i−1 が S型なら,i−1 をそのバケツの末尾から詰めて入れる

クリックで1段階ずつ確認できます.各マスの上には,添字の下に最終的にそこに入る接尾辞と,その型(L型・S型)・LMS かどうかを書いています.

この方法で正しく並ぶのは,接尾辞 i−1 が「文字 S[i−1] + 接尾辞 i」だからです.
同じバケツ(同じ先頭文字)の L型どうしの順番は,後ろに続く接尾辞 i の順番で決まります.
左から走査すると接尾辞 i は小さい順に出てくるので,出てきた順にバケツの先頭から詰めるだけで正しい順になります.
また,L型なら 接尾辞 i < 接尾辞 i−1 なので,i−1 を入れるより前に必ず i が SA に入っています.S型の走査はこれを右からにしたものです.

手順5:LMS の正しい順番を求める

手順4では「LMS の正しい順番」を使いましたが,これはどう求めればよいでしょうか.

実は,LMS を適当な順番で置いて同じ誘導ソートをしても,LMS どうしは「LMS部分文字列」(ある LMS から次の LMS までの部分)の順には正しく並びます.
banana$ の LMS部分文字列は,1 → ana,3 → ana$,6 → $ です.

  • LMS部分文字列がすべて異なる場合:その順番がそのまま LMS の正しい順番になります.banana$ はこちらで,6 → 3 → 1 と決まります.
  • 同じ LMS部分文字列がある場合:LMS部分文字列に小さい順で番号を付け,その番号を並べた短い文字列を作ります.その文字列のSuffix Arrayを再帰的にSA-IS法で求めると,LMS の正しい順番が分かります.

最後に,求めた LMS の順番を使って手順4の誘導ソートをもう一度行えば完成です.
