Dijkstra's Algorithm（ダイクストラ法）

辺の重みが非負のグラフで,1つの始点から全頂点への最短距離を求めるアルゴリズムについて解説します.

ダイクストラ法について

ダイクストラ法は,「まだ確定していない頂点のうち,今わかっている距離が最小の頂点は,その距離で確定してよい」という性質を使って,始点に近い頂点から順に最短距離を確定させていく方法です.
距離が最小の頂点を優先度付きキュー(ヒープ)で取り出すことで,$O((N + M) \log N)$ で全頂点への最短距離が求まります.

代表的な使い道は次のとおりです.

  • 道路の長さや移動時間など,重みが 0 以上のグラフの最短経路
  • 頂点を (位置, 状態) に分けたグラフでの最小コスト
  • 最短経路の復元,最短経路上にある辺・頂点の判定

頂点数を N,辺の数を M とします.

操作計算量
1つの始点から全頂点への最短距離(ヒープを使う)$O((N + M) \log N)$
1つの始点から全頂点への最短距離(ヒープを使わない)$O(N^2)$
最短経路の復元(1頂点分)$O(N)$

距離が最小の頂点から確定させる

手順は次のとおりです.dist[v] は「今わかっている,始点から v までの距離の最小値」です.

  1. dist[始点] = 0,ほかは ∞ にして,(0, 始点) をヒープに入れる.
  2. ヒープから距離 d が最小の (d, v) を取り出す.d > dist[v] なら古い情報なので飛ばす.
  3. v から重み w の辺で行ける頂点 nv について,d + w < dist[nv] なら dist[nv] を更新して (dist[nv], nv) をヒープに入れる(この操作を緩和という).
  4. ヒープが空になるまで 2, 3 をくり返す.

頂点 0 を始点として,1段階ずつ見てみます.辺の横の数字は重み,頂点の横の数字は今わかっている距離です.

なぜ取り出した頂点の距離は確定してよいのか

ヒープから取り出した頂点 v の距離 d が,ほかのどの未確定の頂点の距離よりも小さいとします.
もし v へのもっと短い経路があるとすると,その経路はどこかで未確定の頂点 u を通るはずですが,u までの距離がすでに d 以上なので,そこから先の辺の重みが非負である限り,v に着くころには d 以上になってしまいます.
したがって d より短い経路はなく,v の距離は d で確定します.この議論は重みが負の辺があると成り立たないので,ダイクストラ法は負の重みには使えません.

なぜ $O((N + M) \log N)$ なのか

緩和に成功するたびにヒープに1つ入れるので,ヒープに入る要素は合計で高々 M + 1 個です.
ヒープへの出し入れはそれぞれ $O(\log M)$ で,$\log M \le \log N^2 = 2 \log N$ なので,全体で $O((N + M) \log N)$ になります.

注意点

  • 負の重みの辺があると正しく求まりません.その場合はベルマン-フォード法を使います.
  • 取り出した (d, v) が古い情報(d > dist[v])なら必ず飛ばします.飛ばさないと同じ頂点の辺を何度も見ることになり,計算量が悪化します.
  • ヒープには (距離, 頂点) の順でタプルを入れます.Pythonのタプルは先頭の要素から比べられるので,距離の小さい順に取り出せます.

実装

heapq を使って実装します.上の図と同じグラフです.

from heapq import heappush, heappop

N = 6
edges = [(0, 1, 7), (0, 2, 2), (1, 2, 3), (1, 3, 4), (2, 4, 9), (3, 4, 1), (3, 5, 6), (4, 5, 2)]
G = [[] for _ in range(N)]
for u, v, w in edges:
    G[u].append((v, w))
    G[v].append((u, w))

INF = float("inf")

def dijkstra(s):
    dist = [INF] * N
    dist[s] = 0
    hq = [(0, s)]  # (距離, 頂点)
    while hq:
        d, v = heappop(hq)  # 距離が最小のものを取り出す
        if d > dist[v]:  # 古い情報なら飛ばす
            continue
        for nv, w in G[v]:
            if d + w < dist[nv]:
                dist[nv] = d + w
                heappush(hq, (dist[nv], nv))
    return dist

print(dijkstra(0))
[0, 5, 2, 9, 10, 12]

経路の復元

緩和に成功したときに「どの頂点から来たか」を prev に記録しておくと,ゴールから逆にたどって最短経路を復元できます.

from heapq import heappush, heappop

N = 6
edges = [(0, 1, 7), (0, 2, 2), (1, 2, 3), (1, 3, 4), (2, 4, 9), (3, 4, 1), (3, 5, 6), (4, 5, 2)]
G = [[] for _ in range(N)]
for u, v, w in edges:
    G[u].append((v, w))
    G[v].append((u, w))

INF = float("inf")
dist = [INF] * N
prev = [-1] * N
dist[0] = 0
hq = [(0, 0)]
while hq:
    d, v = heappop(hq)
    if d > dist[v]:
        continue
    for nv, w in G[v]:
        if d + w < dist[nv]:
            dist[nv] = d + w
            prev[nv] = v  # どこから来たかを記録
            heappush(hq, (dist[nv], nv))

path = []
v = 5
while v != -1:
    path.append(v)
    v = prev[v]
print(dist[5], path[::-1])
12 [0, 2, 1, 3, 4, 5]

辺が多いとき($O(N^2)$ のダイクストラ法)

ほぼすべての頂点の組に辺があるような密なグラフ(M が $N^2$ 程度)では,ヒープを使わずに「未確定の頂点の中から距離最小のものを毎回 $O(N)$ で探す」方が速くなります.
この場合の計算量は $O(N^2)$ で,ヒープ版の $O(N^2 \log N)$ より有利です.

ライブラリでの実装

AtCoder Library (ACL) にはダイクストラ法のライブラリはありませんが,SciPy の scipy.sparse.csgraph に dijkstra があります.
return_predecessors=True にすると,経路の復元に使える「1つ前の頂点」の配列も返します.

from scipy.sparse import csr_matrix
from scipy.sparse.csgraph import dijkstra

N = 6
edges = [(0, 1, 7), (0, 2, 2), (1, 2, 3), (1, 3, 4), (2, 4, 9), (3, 4, 1), (3, 5, 6), (4, 5, 2)]
row = [u for u, v, w in edges]
col = [v for u, v, w in edges]
data = [w for u, v, w in edges]
G = csr_matrix((data, (row, col)), shape=(N, N))

dist, pred = dijkstra(G, directed=False, indices=0, return_predecessors=True)
print(dist)
print(pred)
[ 0.  5.  2.  9. 10. 12.]
[-9999     2     0     1     3     4]

結果は float の配列で,到達できない頂点は inf,pred の -9999 は「1つ前の頂点がない」という意味です.
csr_matrix は同じ頂点の組に辺が複数あると重みを足してしまうので,多重辺があるときは最小の重みだけを残してから渡してください.

操作一覧

操作操作内容計算量
dijkstra(G, directed=True, indices=s)s から全頂点への最短距離を返す$O((N + M) \log N)$
dijkstra(G, indices=s, return_predecessors=True)最短距離と,各頂点の1つ前の頂点を返す$O((N + M) \log N)$
dijkstra(G, indices=s, limit=L)距離が L 以下の頂点だけを調べる(それ以外は inf)$O((N + M) \log N)$
dijkstra(G, directed=True)indices を省くと全頂点の組の最短距離($N \times N$ の配列)を返す$O(N (N + M) \log N)$

ほかの最短経路アルゴリズムとの比較

辺の重みの性質によって,使えるアルゴリズムと計算量が変わります.

アルゴリズム扱える重み求めるもの計算量
BFSすべて同じ(重みなし)1つの始点から$O(N + M)$
0-1 BFS0 か 11つの始点から$O(N + M)$
ダイクストラ法0 以上1つの始点から$O((N + M) \log N)$
ベルマン-フォード法負もOK(負閉路の検出も可)1つの始点から$O(NM)$
ワーシャル-フロイド法負もOK(負閉路がないこと)全頂点の組$O(N^3)$

重みが 0 以上ならまずダイクストラ法を考え,重みがすべて同じならBFS,0 か 1 なら 0-1 BFS,負の重みがあるならベルマン-フォード法を使います.
