Breadth-First Search (BFS)（幅優先探索）

始点から近い頂点の順にグラフを調べていく探索アルゴリズムについて解説します.

BFSについて

BFSは,始点から「1本の辺でたどり着ける頂点」→「2本でたどり着ける頂点」→ … のように,始点に近い順に頂点を訪問していく探索方法です.
近い順に訪問するので,辺に重みがない(すべて1の)グラフでは,はじめて訪問したときの辺の本数がそのまま最短距離になります.

代表的な使い道は次のとおりです.

  • 重みなしグラフの,1つの始点から全頂点への最短距離
  • 迷路(グリッド)の最短手数
  • 連結成分の判定や,二部グラフの判定

頂点数を N,辺の数を M とします.

操作計算量
1つの始点から全頂点への最短距離(重みなし)$O(N + M)$
最短経路の復元(1頂点分)$O(N)$

キューを使った探索

BFSでは,これから調べる頂点をキュー(先に入れたものから先に出てくる入れ物)で管理します.

  1. 始点の距離を 0 にして,キューに入れる.
  2. キューの先頭から頂点 v を取り出す.
  3. v の隣の頂点のうち,まだ距離が決まっていないものの距離を「v の距離 + 1」にして,キューの末尾に入れる.
  4. キューが空になるまで 2, 3 をくり返す.

キューには距離 d の頂点がすべて入ったあとに距離 d+1 の頂点が入るので,取り出される頂点の距離は 0, 1, 1, 2, 2, … と小さい順に並びます.
そのため,ある頂点にはじめて到達したときの距離が最短距離であり,あとから見つけた経路で書き換える必要はありません.

頂点 0 を始点として,BFSを1段階ずつ見てみます.頂点の横の数字は距離(-1 は未訪問)です.

なぜ $O(N + M)$ なのか

各頂点はキューに高々1回しか入らず,取り出したときにその頂点から出る辺を1回ずつ見ます.
頂点の取り出しが合計 N 回,辺を見る回数が合計 M 回(無向グラフでは両向きで 2M 回)なので,全体で $O(N + M)$ です.

注意点

  • キューには collections.deque を使います.list.pop(0) は $O(N)$ かかるので遅くなります.
  • 距離を決めるのは「キューに入れるとき」です.取り出すときに決めると,同じ頂点が何度もキューに入ってしまいます.
  • 辺に重みがある場合はBFSでは最短距離を求められません.重みが 0 か 1 なら0-1 BFS,非負ならダイクストラ法を使います.

実装

グラフは隣接リスト(G[v] に v の隣の頂点を並べたリスト)で持ちます.上の図と同じグラフで,頂点 0 からの距離を求めます.

from collections import deque

N = 7
edges = [(0, 1), (0, 2), (1, 2), (1, 3), (2, 4), (3, 5), (4, 5), (5, 6)]
G = [[] for _ in range(N)]
for u, v in edges:
    G[u].append(v)
    G[v].append(u)

def bfs(s):
    dist = [-1] * N  # -1 は未訪問
    dist[s] = 0
    que = deque([s])
    while que:
        v = que.popleft()  # 先頭から取り出す
        for nv in G[v]:
            if dist[nv] == -1:  # はじめて見つけた頂点だけ
                dist[nv] = dist[v] + 1
                que.append(nv)  # 末尾に入れる
    return dist

print(bfs(0))
[0, 1, 1, 2, 2, 3, 4]

経路の復元

距離だけでなく経路そのものが欲しいときは,距離を決めたときに「どの頂点から来たか」を prev に記録しておきます.
ゴールから prev をたどって始点まで戻り,最後に逆順にすれば最短経路になります.

from collections import deque

N = 7
edges = [(0, 1), (0, 2), (1, 2), (1, 3), (2, 4), (3, 5), (4, 5), (5, 6)]
G = [[] for _ in range(N)]
for u, v in edges:
    G[u].append(v)
    G[v].append(u)

dist = [-1] * N
prev = [-1] * N  # prev[v] : v の1つ前の頂点
dist[0] = 0
que = deque([0])
while que:
    v = que.popleft()
    for nv in G[v]:
        if dist[nv] == -1:
            dist[nv] = dist[v] + 1
            prev[nv] = v
            que.append(nv)

# 6 から prev をたどって 0 まで戻り,逆順にする
path = []
v = 6
while v != -1:
    path.append(v)
    v = prev[v]
print(path[::-1])
[0, 1, 3, 5, 6]

グリッドでのBFS

迷路のようなグリッドでは,マス (i, j) を頂点,上下左右の移動を辺とみなします.隣接リストを作らず,その場で4方向を調べればよいです.
次の例は,左上の S から G までの最短手数を求めています(# は壁).

from collections import deque

S = ["S.#..",
     ".##.#",
     "...#G",
     ".#...",
     "....."]
H, W = len(S), len(S[0])

dist = [[-1] * W for _ in range(H)]
dist[0][0] = 0
que = deque([(0, 0)])
while que:
    i, j = que.popleft()
    for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        ni, nj = i + di, j + dj
        if 0 <= ni < H and 0 <= nj < W and S[ni][nj] != "#" and dist[ni][nj] == -1:
            dist[ni][nj] = dist[i][j] + 1
            que.append((ni, nj))

print(dist[2][4])
8

ライブラリでの実装

AtCoder Library (ACL) にはBFSのライブラリはありませんが,SciPy の scipy.sparse.csgraph にグラフ探索の関数があります.
グラフは隣接リストではなく,csr_matrix(疎行列)で渡します.directed=False にすると無向グラフとして扱われるので,辺は片方向だけ入れれば十分です.

from scipy.sparse import csr_matrix
from scipy.sparse.csgraph import breadth_first_order, dijkstra

N = 7
edges = [(0, 1), (0, 2), (1, 2), (1, 3), (2, 4), (3, 5), (4, 5), (5, 6)]
row = [u for u, v in edges]
col = [v for u, v in edges]
G = csr_matrix(([1] * len(edges), (row, col)), shape=(N, N))

order, pred = breadth_first_order(G, 0, directed=False)
print(order)  # 訪問した順
print(pred)   # 1つ前の頂点 (始点は -9999)
print(dijkstra(G, directed=False, indices=0, unweighted=True))  # 距離
[0 1 2 3 4 5 6]
[-9999     0     0     1     2     3     5]
[0. 1. 1. 2. 2. 3. 4.]

breadth_first_order は距離を返さないので,距離が欲しいときは dijkstra に unweighted=True を付けて辺の重みを無視させます.結果は float の配列で,到達できない頂点は inf になります.

操作一覧

操作操作内容計算量
csr_matrix((data, (row, col)), shape=(N, N))辺のリストから疎行列のグラフを作る(同じ辺が複数あると値が足される)$O(N + M)$
breadth_first_order(G, s, directed=True)s からBFSで訪問した順と,各頂点の1つ前の頂点を返す$O(N + M)$
dijkstra(G, directed=True, indices=s, unweighted=True)重みを無視した s からの最短距離を返す$O((N + M) \log N)$

DFSとの比較

BFSとDFSはどちらも全頂点を $O(N + M)$ で訪問しますが,訪問する順番が違います.

BFSDFS
使う入れ物キュー(先入れ先出し)スタック(後入れ先出し)または再帰
訪問の順番始点に近い順行けるところまで進んでから戻る
重みなし最短距離求められる求められない
向いている問題最短距離・最短手数連結判定,サイクル検出,木の上の計算など

到達できるかどうかを調べるだけならどちらでもよく,最短距離が必要ならBFSを使います.
