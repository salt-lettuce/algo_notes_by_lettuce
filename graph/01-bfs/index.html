0-1 BFS（0-1 幅優先探索）

辺の重みが 0 か 1 のグラフで最短距離を求めるアルゴリズムについて解説します.

0-1 BFSについて

0-1 BFSは,BFSのキューを両端キュー(deque)に変え,重み 0 の辺で進んだ頂点は先頭に,重み 1 の辺で進んだ頂点は末尾に入れる方法です.
重みが 0 か 1 のときに限り,ダイクストラ法と同じ結果を,優先度付きキューを使わずに $O(N + M)$ で求めることができます.

代表的な使い道は次のとおりです.

  • 迷路で「壁を壊すのにコスト 1,普通の移動はコスト 0」のような問題
  • 「向きを変えるときだけコスト 1」のような,操作の一部だけにコストがかかる移動
  • 頂点を (位置, 状態) に分けたグラフで,状態の切り替えだけにコストがかかる問題

頂点数を N,辺の数を M とします.

dequeの先頭と末尾を使い分ける

手順は次のとおりです.

  1. 始点の距離を 0 にして deque に入れる.
  2. deque の先頭から頂点 v を取り出す.v がすでに確定済みなら飛ばし,そうでなければ確定させる.
  3. v から重み w の辺で行ける頂点 nv について,dist[v] + w が今の dist[nv] より小さければ更新し,w = 0 なら先頭に,w = 1 なら末尾に入れる.
  4. deque が空になるまで 2, 3 をくり返す.

重み 0 の辺で進んだ頂点は v と同じ距離なので,ほかの頂点より先に調べたい → 先頭に入れる.重み 1 なら距離が1増えるので後回し → 末尾に入れる,という考え方です.
こうすると deque の中身はつねに「先頭側に距離 d の頂点,末尾側に距離 d+1 の頂点」と距離の小さい順に並ぶので,先頭から取り出すだけで距離が最小の頂点を選べます.

頂点 0 を始点として,1段階ずつ見てみます.辺の横の数字は重み,頂点の横の数字は今わかっている距離です.

なぜ $O(N + M)$ なのか

頂点が deque に入るのは距離が更新されたときだけなので,入る回数は合計で高々 M + 1 回です.
確定済みの頂点は取り出してもすぐ飛ばすので,辺を見るのは各頂点につき1回(合計 M 回)です.deque の先頭・末尾への出し入れはどちらも $O(1)$ なので,全体で $O(N + M)$ になります.

注意点

  • BFSと違い,はじめて見つけたときの距離が最短とは限りません(上の例の頂点 1, 5).そのため「距離が小さくなったら更新する」形で書きます.
  • 同じ頂点が deque に複数回入ることがあるので,確定済みの頂点は取り出したときに飛ばします.
  • 重みが 0, 1 以外(例えば 0 と 2)のときはそのままでは使えません.一般の非負の重みにはダイクストラ法を使います.

実装

上の図と同じグラフで,頂点 0 からの距離を求めます.

from collections import deque

N = 6
edges = [(0, 1, 1), (0, 2, 0), (1, 2, 0), (1, 3, 1), (2, 4, 1), (3, 5, 0), (4, 5, 1)]
G = [[] for _ in range(N)]
for u, v, w in edges:
    G[u].append((v, w))
    G[v].append((u, w))

INF = float("inf")

def bfs01(s):
    dist = [INF] * N
    done = [False] * N
    dist[s] = 0
    que = deque([s])
    while que:
        v = que.popleft()
        if done[v]:  # 確定済みなら飛ばす
            continue
        done[v] = True
        for nv, w in G[v]:
            if dist[v] + w < dist[nv]:
                dist[nv] = dist[v] + w
                if w == 0:
                    que.appendleft(nv)  # 重み 0 は先頭へ
                else:
                    que.append(nv)      # 重み 1 は末尾へ
    return dist

print(bfs01(0))
[0, 0, 0, 1, 1, 1]

グリッドでの0-1 BFS

よく出る形は「普通のマスへの移動はコスト 0,壁 # を壊して進むとコスト 1」のようなグリッドの問題です.
移動先のマスによって重み w を決め,あとは同じように先頭・末尾を使い分けます.

from collections import deque

# 壁 "#" を壊すのにコスト 1 かかるときの,左上から右下への最小コスト
S = ["..#..",
     "###.#",
     "..#..",
     ".###.",
     "...#."]
H, W = len(S), len(S[0])
INF = float("inf")

dist = [[INF] * W for _ in range(H)]
dist[0][0] = 0
que = deque([(0, 0)])
while que:
    i, j = que.popleft()
    for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        ni, nj = i + di, j + dj
        if not (0 <= ni < H and 0 <= nj < W):
            continue
        w = 1 if S[ni][nj] == "#" else 0
        if dist[i][j] + w < dist[ni][nj]:
            dist[ni][nj] = dist[i][j] + w
            if w == 0:
                que.appendleft((ni, nj))
            else:
                que.append((ni, nj))

print(dist[H - 1][W - 1])
1

右上の壁 (0, 2) を1つ壊せば,あとは壁を通らずに右下まで行けるので答えは 1 です.
この書き方では確定済みの判定を省いています.距離が小さくなるときだけ更新するので答えは正しく求まり,同じマスを何度か調べ直すことがあっても,各マスから出る辺は4本しかないので計算量は $O(HW)$ のままです.

ライブラリでの実装

0-1 BFS専用のライブラリはありませんが,重みが 0 か 1 のグラフは非負重みのグラフなので,SciPy の dijkstra でも最短距離を求められます.
計算量は $O((N + M) \log N)$ になり,0-1 BFSより少し遅くなります.

from scipy.sparse import csr_matrix
from scipy.sparse.csgraph import dijkstra

N = 6
edges = [(0, 1, 1), (0, 2, 0), (1, 2, 0), (1, 3, 1), (2, 4, 1), (3, 5, 0), (4, 5, 1)]
row = [u for u, v, w in edges]
col = [v for u, v, w in edges]
data = [w for u, v, w in edges]
G = csr_matrix((data, (row, col)), shape=(N, N))

print(dijkstra(G, directed=False, indices=0))
[0. 0. 0. 1. 1. 1.]

重み 0 の辺は,このように疎行列に値 0 として明示的に入れておけば辺として扱われます.ただし,2次元配列(密行列)でグラフを渡すと 0 は「辺がない」という意味になるので注意してください.
