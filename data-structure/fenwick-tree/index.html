Fenwick Tree (Binary Indexed Tree)（フェニック木）

区間和の更新が高速に行える木構造について解説します.

参考：Qiita

BITについて

BITはセグメント木の一種で,通常の配列と累積和配列がもつオーダーの遅い部分を補うための木構造で,データの一点更新と区間和の計算が $O(\log N)$ で実行することができます.

代表的な使い道は次のとおりです.

  • 値の更新がある配列の区間和
  • 転倒数(反転数)の計算:左から順に「自分より大きい値がすでにいくつ出たか」を数える
  • 座標圧縮と組み合わせた「x 以下の値がいくつあるか」の管理
操作通常の配列累積和配列BIT
更新$O(1)$ → A[2] = 10$O(N)$ → 再計算$O(\log N)$
区間和$O(N)$ → sum(A[0:3])$O(1)$ → ac[3]-ac[0]$O(\log N)$

各要素が持つ値

BITは長さ N+1 の配列1本で実装でき,木構造なのにノード用の配列を別に持たなくてよい点が特異であるといえます.
インデックスは 1-indexed で,BIT[0] は使いません(常に 0).
BIT[i] には,A の i 番目を右端とするある長さの区間の和が入っています.

担当する区間の長さは,i を2進数で表したときの一番右の1の桁(最下位ビット)で決まります.
この値は i & -i で求められ,BIT[i] は A の (i − (i & -i), i] 番目の和を持ちます.

Pythonの整数は2の補数として扱われるので,-i は「i のビットを反転して1を足したもの」になります.
例えば i = 6 = 0110(2) のとき,-i は …1010(2) なので,6 & -6 = 0010(2) = 2 です.

A = [1, 2, ..., 8] について,この表のとおりに値を入れるとBITは次のようになります.

A = list(range(1,9))
print(A)

BIT[2]=1+2 # Aの 1,2番目の和
BIT[3]=3 # Aの 3番目の数

BIT[5]=5 # Aの 5番目の数
BIT[6]=5+6 # Aの 5,6番目の和
BIT[7]=7 # Aの 7番目の和
BIT[8]=1+2+3+4+5+6+7+8 # Aの 1,2,3,4,5,6,7,8番目の和

print(BIT)
[1, 2, 3, 4, 5, 6, 7, 8]
[0, 1, 3, 3, 10, 5, 11, 7, 36]

なぜ $O(\log N)$ なのか

  • 区間和:i から i & -i を引くと右端の1が1つ消えます.1は高々 log2N 個しかないので,ループも高々 log2N 回で終わります.
  • 更新:i に i & -i を足すと右端の1が1つ上の桁へ繰り上がり,担当区間が2倍以上に広がります.N を超えるまでに高々 log2N 回で終わります.

どちらも,具体的な動きは下の「区間和の計算」「値の更新」の図で1段階ずつ確認できます.

注意点

  • BITで直接求められるのは「1〜i 番目の和」(累積和)です.区間 [l, r] の和は「1〜r の和 − 1〜(l−1) の和」と引き算で求めるので,和やxorのように逆の操作ができる演算でしか区間クエリは使えません.区間最小値 や 区間最大値 にはセグメント木を使います.
  • このページの自作実装は1-indexedですが,ACLの FenwickTree は0-indexedです.

区間和の計算

A[3]〜A[7]の和を求めるには,通常と同じように,(A[0]〜A[7]の和) − (A[0]〜A[2]の和) を計算します.
ここでA[0]〜A[7]の和を求めるときに,ビット演算を用います.

7 = 111(2) について,右端の1を0にする操作を繰り返します.
111(2) → 110(2) → 100(2) → 000(2)
十進数では 7 → 6 → 4 → 0 です.
この値をインデックスとして足し合わせると,累積和を求めることができます.

ac7 = BIT[7] + BIT[6] + BIT[4] + BIT[0] #最悪O(log(n))
print(ac7)
#BIT[7]=7 BIT[6]=5+6 BIT[4] = 1+2+3+4 BIT[0]=0
28

同様にA[0]〜A[2]について求めれば,A[3]〜A[7]の和を求めることができます.

ac2 = BIT[2] + BIT[0] # 10 -> 00
ac3_7 = ac7 - ac2
print(ac3_7)
25

区間和の計算に必要なオーダーは累積和の計算が2回で,高々 $O(\log N)$ であることがわかります.

値の更新

A[5]に6を足す操作について考えましょう.
まず5を二進数で表すと,101(2) となります.
ここで右端の1に1を足す操作を繰り返し,N=8を超える前にやめます.
101(2) → 110(2) → 1000(2)
十進数では 5 → 6 → 8 です.
これらの値をインデックスとして6を足していくことで値の更新ができます.

#A[5]が入ってる要素が参照できる
BIT1 = BIT.copy() #BITの変更を防ぐ用
BIT1[5]+=6 # BIT[5] = 5   +6
BIT1[6]+=6 # BIT[6] = 5+6   +6
BIT1[8]+=6 # BIT[8] = 1+2+3+4+5+6+7+8   +6
print(BIT1)
[0, 1, 3, 3, 10, 11, 17, 7, 42]

要素の更新のオーダーも高々 $O(\log N)$ であることがわかります.

クラスでの実装

クラスを用いると以下のように実装することができます.
後半では A = [1, 2, ..., 8] からBITを作り,前例と同じ区間和と更新を行っています.

class BIT:
    # 長さN+1の配列を初期化
    def __init__(self, N):
        self.size = N
        self.bit = [0]*(N+1)

    # i番目までの和を求める
    def sum(self, i):
        res = 0
        while i > 0: # bit[0]=0なので計算しない
            res += self.bit[i] # フェニック木のi番目の値を加算
            i -= -i & i # 最も右にある1の桁を0にする
        return res

    # i番目の値にxを足して更新する
    def add(self, i, x):
        while i <= self.size: # iがNを超えないように制限
            self.bit[i] += x # フェニック木のi番目にxを足して更新
            i += -i & i # 最も右にある1の桁に1を足す

A = [1, 2, 3, 4, 5, 6, 7, 8]
N = len(A)

bit = BIT(N)
for i in range(N):
    bit.add(i+1, A[i]) # 1-indexedなので i+1 番目に A[i] を足す
print(bit.bit)

print(bit.sum(7) - bit.sum(2)) # 3~7番目の和
bit.add(5, 6) # 5番目に6を足す
print(bit.bit)
[0, 1, 3, 3, 10, 5, 11, 7, 36]
25
[0, 1, 3, 3, 10, 11, 17, 7, 42]

ライブラリでの実装

AtCoder Library (ACL) にはBITのライブラリが存在します.
こちらは0-indexedで設計されているため,bit[0] から値を入れる必要があることに注意してください.

from atcoder.fenwicktree import FenwickTree

A = [1, 2, 3, 4, 5, 6, 7, 8]
N = len(A)

bit = FenwickTree(N)
for i in range(N):
    bit.add(i, A[i]) # 0-indexedなので i 番目に A[i] を足す
print(bit.data)

print(bit.sum(2, 7)) # 区間 [2, 7) の和 (前例の3~7番目)
bit.add(4, 6) # 前例の5番目に6を足す操作
print(bit.data)
[1, 3, 3, 10, 5, 11, 7, 36]
25
[1, 3, 3, 10, 11, 17, 7, 42]

操作一覧

操作操作内容計算量
FenwickTree.add(i, x)i 番目の要素に x を加算$O(\log N)$
FenwickTree.sum(l, r)区間和 [l, r) の計算$O(\log N)$
FenwickTree.data現在のBIT配列を返す$O(N)$

セグメント木との比較

計算量(オーダー)はどちらも同じで,違いは定数倍と扱える演算です.

操作BITセグメント木
構築$O(N)$ (1つずつ add すると $O(N \log N)$)$O(N)$
一点更新$O(\log N)$$O(\log N)$
区間クエリ$O(\log N)$$O(\log N)$
二分探索(累積和が x 以上になる位置など)$O(\log N)$$O(\log N)$ (ACLの max_right)
メモリN+12N

BITが優れている点

  • 実装が短い:sum と add がそれぞれ数行のループで書ける.セグ木は単位元・演算・区間の左右の処理が必要で,書き間違えやすい.
  • 定数倍が速い:1回のループは足し算とビット演算だけ.セグ木は op 関数の呼び出しが入るので,特にPythonでは差が出やすい.
  • メモリが少ない:長さ N+1 の配列1本で済む(オーダーはどちらも $O(N)$).
  • 定番の応用がそのまま書ける:転倒数の計算や,座標圧縮と組み合わせた個数の管理が短いコードで書ける.

セグメント木が向いている場合

  • min / max / gcd など逆元の無い演算:BITの区間和は「[0, r) の和 − [0, l) の和」で求めるので,引き算ができる演算でしか区間クエリが取れない.
  • 値の書き換え:和なら差分を足せば済むが,一般の演算ではセグ木の set が素直.
  • 区間更新・区間取得:遅延評価セグ木を使う(和だけならBITを2本使う方法もある).

区間和・個数カウントだけならBIT,それ以外の演算や区間更新が必要ならセグメント木,と使い分けるとよいです.
